# The Daily Impact — maintainer notes for Claude

A daily HTML briefing (GitHub Pages) generated by GitHub Actions with Claude.

## How a day runs
- **07:50 Bangkok**: a Claude scheduled task starts `.github/workflows/daily-report.yml` (`workflow_dispatch`).
  GitHub's own schedule (09:37 Bangkok) is only a backup and skips if today's edition exists.
- `generate_report.py`: Claude (via `claude_llm.py`, headless Claude Code, `ANTHROPIC_API_KEY` from the
  Console organization linked to the owner's Max plan, model alias `sonnet`) writes the whole briefing from the `SYSTEM_PROMPT` secret,
  using web search. A briefing missing `</html>` or any of News / Editorial / Dhamma Corner /
  Personal Reflection is retried once, then the run fails rather than publishing a broken page.
- `essential_reading.py` adds "Today's Essential Reading" (7 categories, before Personal Reflection):
  curated feeds (`reading_sources.json`) → Claude shortlist → script opens every article and checks it
  (loads, dated ≤14 days, no paywall, enough text, never featured before) → Claude picks and writes
  80–120-word summaries (`reading_prompt.md`) → `reading_history.json` records picks.
  Category 3 focuses on autism, ADHD, PTSD and bipolar disorder (`focus` in `reading_sources.json`).
  This step must never block the briefing.
- The workflow commits `index.html`, `YYYY-MM-DD.html`, `archive.html`, `reading_history.json`.

## When something breaks
- `.github/workflows/run-watchdog.yml` + `tools/run_watchdog.py` open/comment an issue labelled
  `daily-impact-alert` after a failed or degraded run (or no run by 16:17 Bangkok), and close it after a
  healthy run.
- For failed/degraded runs, the `repair` job runs `tools/self_repair.py`: Claude diagnoses and edits
  code; the change is merged to main only if `python3 tools/selftest.py` passes; max 2 repairs/day.

## Rules for changes
- Run `python3 tools/selftest.py` (offline, no network or API) after any change; keep it passing and
  extend it when you fix a bug.
- Never weaken the article checks, the briefing completeness check, or the "reading never blocks the
  briefing" behaviour. Never put secrets in the repo (it's public).
- `tools/check_reading_sources.py` checks every feed; run it from GitHub's runners when sources change
  (many sites block other networks).
